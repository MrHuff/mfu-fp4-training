\section{Introduction}

Four-bit floating-point (FP4) Tensor Cores accelerate general matrix
multiplication (GEMM), but GEMM is only part of a large language model (LLM)
training step. Each FP4 linear layer must also compute scales, round and pack
values, build the row- and column-oriented layouts consumed in forward and
backward, and retain the state needed by autograd. Separate kernels repeatedly
move large bfloat16 (BF16) intermediates through high-bandwidth memory (HBM).
The surrounding work can consume the Tensor Core gain even when the FP4 GEMM
itself is efficient \cite{nvidia2025nvfp4}.

We address this gap with \emph{format-aware fusion}. Each activation or
gradient producer emits the scales, physical layouts, and saved state required
by the next operation. The schedule follows the format's scale domain:
\mxfp{} completes a local 32-value scale, global \nvfp{} waits for a
tensor-wide maximum, and cooperative-thread-array-local (CTA-local) \nvfp{}
completes two outer scales within the tile that owns the matrix multiplication.
The profitable fusion boundary therefore differs by format.

We evaluate the resulting paths in Llama-3-family 8B pretraining at sequence length
8,192 and global batch 512. Same-accelerator probes measure every route with a
BF16 output projection and compiled cross entropy (CE), while long
trajectories cover up to 160B tokens. The fastest custom route reaches 37.9K
tokens/s/GPU. The \mxfp{} route with row-gradient stochastic rounding (SR)
and fixed-sign H32 weight-gradient (Wgrad) preconditioning reaches 37.2K
tokens/s/GPU and ends 2.11\% above the raw BF16 endpoint. The TE-native and
four-final-BF16-block trajectories end 1.34\% and 0.87\% above raw BF16,
respectively, at measured throughputs of 27.6K and 27.1K tokens/s/GPU.

This report makes three contributions:

\begin{itemize}
  \item Native, format-specific execution paths that fuse scale production,
        physical layouts, and saved backward state. The fastest custom path
        reaches 37.9K tokens/s/GPU in the common compiled-CE probe.
  \item An operand-specific MXFP4 scale policy and its fused realization.
        Development-only pretraining screens favored upward E8M0 rounding for
        activation and gradient operands. The 2D32 weight path instead selects
        the next smaller scale when the normalized tile maximum is below 0.87,
        trading upper-tail clipping for a twice-finer grid. Across routes,
        adjacent-bin SR acts only on the row-facing Dgrad input, paired
        fixed-sign H16/H32 preconditioning acts only in Wgrad, and each pure or
        depth-assigned format supplies transpose-consistent weight layouts.
  \item A 160B-token comparison of pure and hybrid routes, supported by
        same-state operator analysis, checkpoint-matched validation, and
        downstream evaluation. Appendix~\ref{app:code-release} links the
        public code, pinned kernel sources, recipes, and figure builders.
\end{itemize}
